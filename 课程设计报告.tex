本项目完成了教室预约系统的设计与实现。主要包括以下几个要素：

1. \textbf{研究背景与问题概述}：高校教室资源紧张，传统人工预约流程繁琐、信息更新滞后，易出现预约冲突与资源闲置问题，师生难以实时获取教室状态，管理员统筹效率低，亟需智能化系统优化管理。

2. \textbf{数据结构与算法}：采用 “链表 + 栈 + 队列” 组合：链表存储教室信息与预约记录，支持高效增删查；栈记录操作以实现撤销；队列按序处理预约，自动检测冲突。

3. \textbf{主要功能}：分师生与管理员角色，支持教室查询、预约申请与审核、状态实时查看、预约撤销等核心操作。

4. \textbf{实现效果}：核心操作响应高效，支持多用户并发使用，模块化设计便于扩展，显著提升教室资源利用率。

\vspace{1cm}

\noindent\textbf{关键词：} 数据结构；教室预约；链表；栈；队列；C 语言

\chapter*{Abstract}

The project has completed the design and implementation of a classroom reservation system. It mainly includes the following key elements:

1. \textbf{Background and problem statement}: University classroom resources are in short supply. The traditional manual reservation process is cumbersome with delayed information updates, prone to reservation conflicts and resource idleness. Teachers and students cannot obtain real-time classroom status, and administrators have low coordination efficiency, so an intelligent system is urgently needed to optimize management.

2. \textbf{Data structures and algorithms}: A combination of "linked list + stack + queue" is adopted: linked lists store classroom information and reservation records for efficient addition, deletion and query; stacks record operations for undo; queues process reservations in order with automatic conflict detection

3. \textbf{Main functions}:With teacher/student and administrator roles, it supports core operations such as classroom query, reservation application and review, real-time status check, and reservation cancellation.

4. \textbf{Implementation results}: Core operations respond efficiently, supporting concurrent use by multiple users. The modular design facilitates expansion and significantly improves classroom resource utilization.

Keywords: data structures; classroom reservation; linked list; stack; queue; C language

\chapter*{引言}

随着城市机动车保有量的快速增长和土地资源的日益紧张，停车难已成为困扰城市交通管理的突出问题之一。在商业中心、医院、学校等人流密集场所，停车位供需矛盾尤为明显。传统的人工管理方式不仅效率低下，而且容易出现计费错误、车位信息滞后等问题，难以满足现代化管理的需求。近年来，随着信息技术的发展，越来越多的停车场开始引入智能化管理系统，通过自动识别、实时监控和数据统计等手段提升管理效率与服务质量。在这样的背景下，本课程设计选取“停车场管理系统”作为应用场景，尝试运用数据结构课程中所学的核心知识，设计并实现一个具备基本功能的停车场管理原型系统。

本项目的核心目标是利用合适的数据结构，实现停车场车辆进出、停车费用计算、车位查询与统计等基本功能。系统需要支持多辆车的并发管理，能够准确记录每辆车的进入时间、离开时间及停车位置，并根据停车时长自动计算停车费用。更具体地说，一方面系统要能够高效地处理车辆的进栈（入场）与出栈（离场）操作，确保数据的准确性和实时性；另一方面，系统需要提供友好的用户交互界面，使管理员能够方便地进行车辆信息查询、停车场状态监控等操作。项目希望回答的关键问题包括：在停车场容量有限的情况下，如何通过栈和队列的组合使用实现车辆的有序管理；如何设计合理的数据结构以支持快速的车辆信息检索；以及如何在保证功能完整性的前提下，实现代码的模块化和可维护性。

在数据结构选择上，本项目的核心设计思想是将停车场抽象为一个具有固定容量的栈结构，而将便道抽象为一个队列结构。当停车场已满时，新到达的车辆需要在便道上排队等待；当停车场内有车辆离开时，便道上等待的车辆可以依次进入停车场。栈和队列的组合充分体现了数据结构课程中关于栈的“后进先出”（LIFO）和队列的“先进先出”（FIFO）特性的实际应用。此外，为了支持按车牌号快速查找车辆信息，系统还采用了链表结构来存储车辆的详细记录，从而在插入、删除和遍历操作之间取得较好的平衡。通过这样的设计，项目既能满足停车场管理的实际需求，又能充分展示所学数据结构知识的工程应用价值。

\section*{项目背景与动机}

停车场管理作为城市交通管理的重要组成部分，直接影响着城市交通的流畅性和市民的出行体验。在许多大型商业综合体、医院和办公楼中，停车位资源有限而车流量巨大，如何在有限的空间内实现车辆的有序管理，成为物业管理部门面临的重要挑战。传统的人工登记方式存在诸多弊端：一方面，手工记录容易出错，特别是在车流高峰期，工作人员难以准确记录每辆车的进出时间；另一方面，人工管理无法实时提供停车位的可用情况，导致车主需要在场内反复寻找车位，既浪费时间又增加了场内拥堵的风险。此外，人工计费过程繁琐且容易引发争议，影响了管理效率和服务质量。

从计算机科学的角度来看，停车场管理问题具有典型的数据结构应用特征。停车场本身可以看作一个容量受限的栈，车辆只能从一端进入和离开，且离开时必须按照“后进先出”的原则操作——如果需要让某辆不在栈顶的车离开，就必须先让挡在它前面的车临时驶出。这种场景与栈的操作特性高度吻合，为栈这一基本数据结构的实际应用提供了理想的教学案例。与此同时，为了处理停车场已满时新到达的车辆，需要设置一个便道（或称候车区），让这些车辆按照到达顺序依次等待，这是队列“先进先出”特性的典型应用场景。因此，通过停车场管理系统的设计与实现，可以将课堂上学习的栈和队列这两种基础数据结构有机地结合起来，在解决实际问题的过程中加深对理论知识的理解。

选择停车场管理系统作为课程设计题目，不仅因为其具有实际应用价值和良好的教学示范作用，还因为该系统具有适度的复杂性，能够较全面地锻炼学生的编程能力和系统设计能力。在功能层面，系统需要实现车辆的进出管理、费用计算、信息查询等多个模块，涉及多种数据结构的综合运用；在性能层面，系统需要保证操作的效率，特别是在车辆频繁进出的情况下，各项操作的时间复杂度应控制在合理范围内；在工程层面，系统需要具备良好的代码组织结构和清晰的模块划分，便于后续的功能扩展和维护。通过完成这样一个综合性的课程设计项目，可以帮助学生将数据结构的理论知识转化为实际的编程技能，为今后从事软件开发工作打下坚实的基础。

\section*{研究目标与问题定义}

为了使项目目标更加明确，本工作将“停车场管理系统”的设计与实现任务划分为三个彼此关联但侧重点不同的子目标。第一个子目标是正确选择并实现核心数据结构，包括用于模拟停车场的栈结构和用于模拟便道的队列结构，确保这些数据结构能够准确地反映停车场的实际运行规则。第二个子目标是在这些数据结构的基础上实现完整的功能模块，包括车辆到达处理、车辆离开处理、停车费用计算、车辆信息查询与停车场状态统计等，使系统具备实际可用的管理功能。第三个子目标是对系统进行全面测试，验证各功能模块的正确性，并对关键操作的时间复杂度和空间复杂度进行分析，确保系统在性能上满足实际应用的基本要求。

在形式化定义上，可以将停车场管理系统的核心操作抽象为以下几类基本操作：
\begin{itemize}
  \item \textbf{车辆到达（Arrival）：} 当一辆车牌号为 $plate$ 的车辆到达时，系统需要判断停车场是否已满。如果未满，则将该车辆信息（包括车牌号、到达时间等）压入停车场栈 $S$；如果已满，则将该车辆加入便道队列 $Q$。
  \item \textbf{车辆离开（Departure）：} 当一辆车牌号为 $plate$ 的车辆请求离开时，系统需要在停车场栈 $S$ 中查找该车辆。如果该车辆不在栈顶，则需要将其上方的所有车辆依次弹出并暂存到一个临时栈 $T$ 中，待目标车辆离开后，再将临时栈中的车辆依次压回停车场栈。车辆离开时需要根据停车时长计算费用。
  \item \textbf{车辆查询（Query）：} 给定车牌号 $plate$，查询该车辆当前所处的位置（停车场内、便道上或不存在），并返回相关信息（如停车位置编号、已停车时长等）。
  \item \textbf{状态统计（Statistics）：} 实时显示停车场和便道的当前状态，包括停车场已使用车位数、剩余车位数、便道排队车辆数等。
\end{itemize}

在性能指标方面，系统需要满足以下基本要求：车辆到达操作的时间复杂度应为 $O(1)$，确保新车能够快速入场；车辆离开操作的时间复杂度在最坏情况下为 $O(n)$（其中 $n$ 为停车场容量），但在平均情况下应尽可能接近 $O(1)$；车辆查询操作的时间复杂度应控制在 $O(n)$ 以内；系统的空间复杂度应与停车场容量和车辆数量成正比，避免不必要的内存浪费。此外，系统还应具备良好的可扩展性，便于在后续版本中增加新的功能模块（如车位预约、VIP 车辆优先等）。

通过上述目标设定和问题定义，读者可以清楚地了解本项目的核心任务和技术要求。在后续章节中，将详细阐述如何通过合理的系统设计和算法实现来达成这些目标，并通过实验结果验证系统的有效性和实用性。

\section*{核心数据结构选择}

在停车场管理系统的设计中，数据结构的选择直接影响到系统功能的实现效果和运行效率。本项目的核心设计思想是根据停车场和便道的实际运行特点，选择与其特性相匹配的数据结构。

对于停车场本身，由于车辆只能从一个入口进入和离开，且场内空间有限，新到达的车辆停在最外侧，离开时必须让挡路的车先出，这与栈的“后进先出”特性完全吻合。因此，本项目采用\textbf{顺序栈}来模拟停车场。顺序栈使用数组实现，具有访问速度快、实现简单的优点，非常适合容量固定的停车场场景。栈的主要操作包括压栈（Push）、弹栈（Pop）和取栈顶元素（Top），这些操作的时间复杂度均为 $O(1)$，能够满足车辆快速进出的需求。

对于便道，当停车场已满时，新到达的车辆需要在便道上按到达顺序依次等待，一旦停车场有车位空出，等待时间最长的车辆（即最早到达的车辆）应优先进入。这种“先到先服务”的规则与队列的“先进先出”特性高度一致。因此，本项目采用\textbf{链式队列}来模拟便道。链式队列使用链表实现，相比顺序队列不会出现假溢出现象，且不需要预先设定固定容量，能够灵活应对不同规模的等待车辆。队列的主要操作包括入队（Enqueue）和出队（Dequeue），时间复杂度同样为 $O(1)$。

此外，为了支持按车牌号快速查询车辆信息，系统还需要维护一个车辆信息表。考虑到车辆进出的频繁性和信息检索的需求，本项目采用\textbf{单向链表}来存储所有在场车辆的详细记录。每个链表节点包含车辆的车牌号、进入时间、停车位置等信息。虽然链表的查询操作时间复杂度为 $O(n)$，但其插入和删除操作无需移动大量元素，且能够动态分配内存，在车辆数量不确定的情况下更加灵活高效。

综上所述，本项目通过“顺序栈+链式队列+单向链表”的组合方案，充分发挥了不同数据结构的优势，既保证了系统核心功能的正确实现，又在性能和可扩展性方面达到了较好的平衡。这种设计思路体现了数据结构课程中根据问题特点选择合适数据结构的核心原则，也为后续的算法设计和代码实现奠定了坚实的基础。

typedef struct {

\chapter{详细设计与算法实现}

本章详细描述各功能模块的算法设计思路，展示关键代码实现，并对算法的时间复杂度和空间复杂度进行分析。

\section{栈和队列的基本操作}

\subsection{栈的初始化与基本操作}

栈的初始化非常简单，只需将栈顶指针设为 -1 即可：

\begin{codeblock}
// 初始化停车场栈
void initStack(ParkingStack *s, int capacity) {
    s->top = -1;
    s->capacity = capacity;
}

// 判断栈是否为空
int isEmpty(ParkingStack *s) {
    return s->top == -1;
}

// 判断栈是否已满
int isFull(ParkingStack *s) {
    return s->top == s->capacity - 1;
}
\end{codeblock}

压栈操作将新元素添加到栈顶，时间复杂度为 $O(1)$：

\begin{codeblock}
// 车辆进入停车场（压栈）
int push(ParkingStack *s, Car car) {
    if (isFull(s)) {
        return 0;  // 停车场已满
    }
    s->data[++s->top] = car;
    s->data[s->top].position = s->top + 1;
    return 1;
}
\end{codeblock}

\subsection{队列的初始化与基本操作}

链式队列的初始化需要创建头节点：

\begin{codeblock}
// 初始化便道队列
void initQueue(WaitingQueue *q) {
    q->front = q->rear = NULL;
    q->size = 0;
}

// 入队操作
void enqueue(WaitingQueue *q, Car car) {
    QueueNode *node = (QueueNode*)malloc(sizeof(QueueNode));
    node->data = car;
    node->next = NULL;
    
    if (q->rear == NULL) {
        q->front = q->rear = node;
    } else {
        q->rear->next = node;
        q->rear = node;
    }
    q->size++;
}
\end{codeblock}

\section{车辆到达处理算法}

车辆到达时的处理流程如下：

\begin{enumerate}
  \item 检查停车场是否已满；
  \item 如果未满，将车辆信息压入停车场栈；
  \item 如果已满，将车辆信息加入便道队列。
\end{enumerate}

算法的伪代码表示：

\begin{codeblock}
// 车辆到达处理
void carArrival(ParkingStack *parking, 
                WaitingQueue *waiting, 
                char *plate) {
    Car car;
    strcpy(car.plate, plate);
    car.arriveTime = time(NULL);
    
    if (!isFull(parking)) {
        push(parking, car);
        printf("车辆 %s 已进入停车场，车位号 %d\n", 
               plate, parking->top + 1);
    } else {
        enqueue(waiting, car);
        printf("停车场已满，车辆 %s 进入便道等待\n", 
               plate);
    }
}
\end{codeblock}

\textbf{复杂度分析：} 该算法的时间复杂度为 $O(1)$，空间复杂度为 $O(1)$（不考虑数据结构本身占用的空间）。

\section{车辆离开处理算法}

车辆离开处理是系统中最复杂的操作，需要考虑以下情况：

\begin{enumerate}
  \item 查找目标车辆在停车场中的位置；
  \item 如果车辆不在栈顶，需要将其上方的车辆暂时移出；
  \item 目标车辆离开后，将暂时移出的车辆依次放回；
  \item 如果便道有车等待，让队首车辆进入停车场。
\end{enumerate}

关键代码如下：

\begin{codeblock}
// 车辆离开处理
void carDeparture(ParkingStack *parking, 
                  WaitingQueue *waiting, 
                  char *plate) {
    ParkingStack temp;  // 临时栈
    initStack(&temp, parking->capacity);
    
    int found = 0;
    Car leavingCar;
    
    // 查找目标车辆
    while (!isEmpty(parking)) {
        Car car = pop(parking);
        if (strcmp(car.plate, plate) == 0) {
            leavingCar = car;
            found = 1;
            break;
        }
        push(&temp, car);  // 暂存到临时栈
    }
    
    // 将临时栈的车辆放回停车场
    while (!isEmpty(&temp)) {
        push(parking, pop(&temp));
    }
    
    if (found) {
        // 计算停车费用
        double fee = calculateFee(leavingCar.arriveTime);
        printf("车辆 %s 离开，停车费用 %.2f 元\n", 
               plate, fee);
        
        // 如果便道有车，让队首进入
        if (waiting->size > 0) {
            Car waitingCar = dequeue(waiting);
            push(parking, waitingCar);
            printf("便道车辆 %s 进入停车场\n", 
                   waitingCar.plate);
        }
    }
}
\end{codeblock}

\textbf{复杂度分析：} 在最坏情况下（目标车辆在栈底），需要遍历整个停车场栈，时间复杂度为 $O(n)$，其中 $n$ 为停车场容量。空间复杂度为 $O(n)$，因为需要使用临时栈。

\chapter{总结与展望}

\section{工作总结}

本课程设计完成了一个基于栈和队列的停车场管理系统。系统采用顺序栈模拟停车场，链式队列模拟便道，实现了车辆的进出管理、停车费用计算、车辆信息查询和状态统计等基本功能。通过该项目的设计与实现，将课堂上学习的数据结构理论知识应用到了实际问题的解决中，加深了对栈和队列这两种基本数据结构的理解，同时也锻炼了C语言编程能力和系统设计能力。

在数据结构方面，通过合理选择栈和队列这两种数据结构，充分利用了它们的特性来模拟停车场的实际运行规则。顺序栈的“后进先出”特性完美契合了停车场车辆进出的实际情况，而链式队列的“先进先出”特性则很好地解决了便道车辆的排队等待问题。在算法设计方面，实现了车辆到达、离开、查询等核心功能，并对关键算法的时间复杂度和空间复杂度进行了分析，确保了系统在性能上满足实际应用的基本要求。

\section{主要收获}

通过本次课程设计，主要有以下几方面的收获：

\begin{enumerate}

\section{不足与改进方向}

虽然本系统实现了基本的停车场管理功能，但仍存在一些不足之处，未来可从以下几个方面进行改进：

\begin{enumerate}
  \item \textbf{数据持久化：} 当前系统的数据仅存储在内存中，程序退出后数据丢失。可以考虑引入文件操作，将车辆信息和停车记录保存到文件中，实现数据的持久化存储；
  \item \textbf{查询效率优化：} 目前按车牌号查询车辆需要遍历整个停车场或便道，时间复杂度为 $O(n)$。可以引入哈希表来存储车牌号与车辆位置的映射关系，将查询时间复杂度降低到 $O(1)$；
  \item \textbf{多停车场管理：} 扩展系统以支持多个停车场的联合管理，实现停车场之间的车位共享和车辆调度；
  \item \textbf{图形化界面：} 当前系统采用命令行交互方式，用户体验有限。可以考虑开发图形化界面，提供更加直观友好的操作方式；
  \item \textbf{智能调度算法：} 引入更加智能的车位分配算法，如根据车辆类型、预计停车时长等因素进行优化调度；
  \item \textbf{统计分析功能：} 增加数据统计和分析功能，如停车高峰时段分析、收入统计、车位利用率计算等，为停车场运营管理提供决策支持。
\end{enumerate}

总的来说，通过本次课程设计的学习和实践，不仅巩固了数据结构的理论知识，也培养了实际编程能力和工程实践能力，为今后进一步学习更复杂的数据结构和算法打下了良好的基础。
